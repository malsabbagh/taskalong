# Qualification

This candidate is a fixture-qualified foundation with **production dispatch
disabled**. It does not claim usable live Codex/Claude execution, model review,
provider cancellation, complete runtime isolation or actual GitHub publication.

Candidate receipts are kept by the owner outside the distribution and bind exact
source, interpreter/host versions, artifact, lock and test-input hashes.
Linux-specific lifetime tests are skipped on macOS and require actual Linux
execution; no macOS result qualifies them. Local checks do not qualify a different
hosted OS image. Every intended Python/platform cell needs its own exact-head CI
receipt; matching Python versions alone do not establish platform equivalence.

Maintenance exclusion uses a composed proof: actual byte-pinned predecessor
compatibility and active-client refusal, plus fresh real SQLite subprocesses
that bypass the advisory gate and receive numeric BUSY at the protected read
and write-reservation operations. Only the witnesses use zero busy retry time;
neither the predecessor nor production settings change. Unlocked controls and
an advisory-only counterexample must expose missing kernel exclusion, and
application rows/schema/identities/blob/control inventory must remain unchanged.
The ten-second witness deadline is containment; timeout, wrong/missing evidence,
unrelated errors or unconfirmed cleanup fail qualification. The historical
default busy-handler constructor timeout remains unexplained. The replacement
proves exclusion within the trusted local-filesystem scope, not legacy response
latency, native scheduling behavior or hostile same-user isolation.

```sh
python -m pip install --require-hashes -r requirements-dev.lock
python -m build --no-isolation --sdist --wheel
python tools/normalize_sdist.py dist/*.tar.gz
python tools/check_dist.py --dist-dir dist
python tools/qualify_installed.py --dist-dir dist --artifact wheel --mode fixture
python tools/qualify_installed.py --dist-dir dist --artifact sdist --mode fixture
python tools/qualify_installed.py --dist-dir dist --artifact wheel --core-only
```

The qualifier creates fresh ordinary environments outside the checkout. Source
reads/import fallback are denied. External synthetic CLI/GitHub fixtures remain
outside the installed wheel. ReviewSensei 0.8.8 is checksum-pinned and uses its
actual released fixture backend; this is not live model review. Synthetic
lost-response publication must reconcile one fixture create. Missing required
review blocks acceptance. These checks produce no runtime authority.

Each wheel or rebuilt-sdist journey uses one frozen artifact, harness and lock
snapshot in one fresh environment. A separate inventory child discovers the
copied installed tests. The fixed schedule sorts modules, assigns alternating
modules to two batches, and keeps each module intact; it never uses prior test
outcomes or timings to select cases. One sample journey and both batches must
succeed. Their disjoint executed-ID union must equal the discovered inventory,
including shared subclasses, with exactly the platform-specific skip cases and
reasons. Missing, duplicate or unexpected tests, skips, or terminal receipts fail.
Ordinary full discovery remains unpartitioned in its original order.

Every child repeats checkout/build-root read and import denial, checks installed
identity and package nonmutation, and binds its terminal receipt to the artifact,
harness, lock, schedule and phase. Phase and test start/outcome/stop records are
flushed durably; test stop follows cleanup. Use `--evidence-dir NEW_DIRECTORY` to
retain the allowlisted progress, inventories and parent receipts. Raw streams
and failed synthetic state stay outside the public export. Stdout contains one
terminal JSON document. Failure preserves bounded stream prefixes, their hashes,
truncation flags and the direct-child exit/reap observation; it does not prove
detached descendants ceased. A timeout, pipe uncertainty or nonzero/malformed
terminal result stops the campaign and remains a failure.
Closed phase payloads are validated before aggregation. The copied harness and
lock manifest are rechecked before and after each phase, including the sample's
fixture aliases. Evidence export excludes arbitrary JSON files and private
fields. Cleanup, diagnostic-read or export errors retain the first failure and
separate closed error codes; unavailable hashes and unconfirmed reaping stay
explicit. A receipt-write failure cannot claim durable persistence. The new
export destination is reserved before setup begins.

Inventory has a 60-second ceiling; the sample and each of the two predetermined
behavior batches have a 600-second ceiling. The whole artifact qualification has
a 1,500-second budget across setup and phases, with at most nine seconds of owned
child finalization outside an execution deadline. Finalization permits only
termination, reaping and evidence retention. These are finite harness bounds;
product, individual test, SQLite, cancellation and process deadlines are
unchanged. The earlier combined-child 600-second timeout remains incomplete
qualification with its precise inner position unknown. Partitioning does not
establish its cause or repair a product defect.

Hosted qualification has eight producer jobs and eight installed jobs per
automatic push/PR event, each with its existing 30-minute job ceiling. Producers
build/audit artifacts and run the ordinary suite and documentation checks.
Installed jobs start only after producer success and download the immutable
matching OS/Python bundle from that same run and attempt. The bundle binds event,
commit/tree, logical producer job/profile, all tracked source hashes and exact
wheel/sdist hashes; consumers verify those identities before fresh wheel, rebuilt
sdist and core-only qualification. Retained workflow metadata supplies numeric
job/artifact IDs for acceptance. A failed/skipped dependent lane is unqualified;
all sixteen jobs in both events require actual success. No runner, billing,
permission, credential or repository-rule change follows from this split.

The existing Codex CLI target is 0.163.0. Prior controlled-responder probes did
not establish complete descendant cessation or effective instruction/tool
isolation. Resume must not follow an unconfirmed lifetime. The current Darwin
backend quarantines forks; Linux subreaper tests still do not, by themselves,
qualify a real CLI, filesystem/network containment or remote provider cessation.
Use an existing approved runtime environment and exact profile for a separate
actual start/cancel/resume/tool/isolation campaign. No runtime installation,
credential change, model pull or provider fallback is implied.

The single-step 2.2 admission path currently admits only an explicitly trusted
`codex-v1-fixture/1` registration. The shared executor contract suite observes one
supervised fake CLI, real local cancellation, canonical/wire identity mapping and
independent synthetic verification. It also checks production/native-resume
refusal. The simulated provider declaration does not prove the actual endpoint,
account, model, instructions, tools or containment of any vendor CLI. Revocation
before dispatch or before owned gate release prevents target execution; retained
unknown windows remain quarantined rather than manufacturing cessation evidence.
Adding another shared driver case or installing a binary grants no runtime
authority. Production stays disabled until separately reviewed exact-mode proof.

Claude wire tests are original synthetic frames, not installed-version
transcripts. Its decoder is unregistered and reports untrusted protocol data;
no provider identity, billing proof, native-resume or cessation receipt follows.

The intended CI matrix is standard GitHub-hosted Ubuntu 24.04 x64 and macOS 15
arm64, Python 3.11–3.14. A configured workflow is not evidence that those cells
passed; each requires its own exact-head results. Repository visibility does not
override runtime preflight or qualify an execution mode.

The explicit distribution inventory excludes control stores, credentials, user
homes, raw logs, Git history and unrelated source. Pattern screening is a
secondary check, not proof of arbitrary-secret absence or rights ownership.
Source-archive normalization removes tar ownership, extended metadata and build
timestamps without changing file payloads or modes. The auditor rejects those
headers if they return, optional wheel metadata, and unapproved package contact
or source-URL metadata. These checks complement the source/content review.
The project uses the [MIT License](../LICENSE). The auditor requires exactly
the approved MIT metadata and license bytes in source, wheel and sdist, while
rejecting additional identity/contact/source metadata. License and notice changes
require rebuilding and fresh qualification. Public visibility and registry
publication remain separate owner decisions.

## Claude fixture qualification scope

M5 implements the synthetic `claude-print-fixture/1` contract through the existing
owned supervisor/runner. The same public durable-driver tests cover Codex and
Claude fixtures. Adversarial stream, denial, identity, output/time, cancellation,
restart and lifetime cases are fixture evidence only. A separate independent
check profile and released offline reviewer fixture are required for acceptance.
No real Claude start/cancel/resume, auth/routing, protective context/tool policy
or complete vendor descendant lifetime is qualified. Production stays disabled;
native resume, hard token/cost enforcement and Ollama remain unsupported here.

## Ollama fixture qualification scope

M6 adds local and direct-cloud Ollama profiles through the same Claude driver
and durable lifecycle under the distinct 2.4 projection. Its route reader and
real offline evaluator require exact identities and separately approved start
and provider-lookup evidence. The controlled responder lives inside the fake
worker, opens no socket and never calls a provider or changes server/model state.
Its invocation record retains route/model/session/config/provider identities and
auth presence/match predicates, never a token. These are synthetic request and
environment observations, not actual HTTP or managed-settings isolation proof.

Shared contract cases cover worker/result separation, independent acceptance,
owned and closed-gate cancellation, persistent restart budgets and native refusal
for both profiles. Route/evidence negatives cover forwarding, unknown identity,
availability, auth, endpoint, mode, provenance, revocation and expiry. Format-5
maintenance must preserve complete prior state and exclude the byte-pinned M5
client. Source and installed artifact results qualify only their recorded head,
platform and synthetic mode; they do not enable production or real credentials.
External-server cessation and real token/cost accounting remain unsupported.

## Cursor fixture qualification scope

M7 adds the explicit 2.5 `cursor-print-fixture/1` projection. Original fixtures
exercise strict whole-object terminal output, fresh observed sessions, exact
model/config/provider bindings, private stream association, owned cancellation
and independent acceptance through the shared lifecycle. Captures are consistency
evidence; they do not establish vendor execution or current authority.

No real Cursor start/edit/model route, account access, project instruction/tool/
hook/MCP isolation, native resume or complete vendor lifetime is qualified. The
fixture permits only balanced scoped Edit events and no nonempty stderr. It
performs no provider request and proves no remote cancellation or cost. Unknown
usage stays unknown; production and hard cost/token caps refuse. See the
[protocol boundary](cursor-protocol.md) and [2.5 contracts](contracts.md#cursor-fixture-contracts-v25).
