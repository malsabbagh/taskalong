# Synthetic Muse supervisor handoff

Status: proposed for independent review; live dispatch remains disabled.

Plain Muse output has no established structured result contract. A successful
local process cannot author a vendor worker-result, session identity, blocker
assessment or code-correctness claim. The closed `muse-plain-fixture/1` route
therefore produces a distinct supervisor-authored `execution_handoff` 2.9. It
uses RunService, Workflow, the existing `run_bounded` owner and original
non-forking fixtures. No launcher, scheduler or task-selected import is added.

Seven additive schemas cover capture-config, task-spec, worker-packet,
packet-projection, execution-handoff and the two read-only views. A task binds
one immutable capture-config digest. This closed fixture has no observed vendor
or provider profile, so it does not invent an M2 binding. Its check profile,
review configuration, checks and command sandbox are exact immutable references.
`RunService.configure_muse_capture` is a trusted synthetic registration API;
registration does not supply execution authority. Production qualification and
publication are unrepresentable. Native continuation/provider lookup refuse.
The original registry tuples and all earlier schema/SQL bytes are unchanged.

Format 9 / SQL009 is an explicit compatibility fence using existing tables.
The existing exclusive, backed-up maintenance operation must apply each earlier
upgrade first. No submission auto-upgrades. A pinned original format 8 client
rejects format 9 before changing its database journal. Backups preserve the
predecessor format and restored state stays quarantined. Rollback preserves new
state with a compatible reader; lowering a version integer is unsupported.

After confirmed local cessation, the supervisor retains original packet input,
stdout/stderr and its raw receipt as durable hash-verified blobs. Binary streams
remain opaque bytes. Unstructured supervisor exceptions mean unknown dispatch,
even when an error is an OSError. Only explicit pre-dispatch proof permits
`not_sent`. An incomplete record keeps effects unresolved and prevents replay.

The handoff requires current Store authority, exact admission/configuration,
run/attempt/packet/workspace/lease generation, persisted spawn observation,
confirmed complete process cessation and a successful scope snapshot. Its
snapshot binds observed content and changed-file manifest. Validation recomputes
these associations from authoritative Store records and frozen prepare, spawn,
capture and finish operation requests. Receipt self-claims cannot establish
completion. Missing/tampered captures, stale authority, changed workspace or
unknown termination prevent the transition. Validation repeats before candidate
freezing, verification and acceptance; the read-only result view also refuses
invalid current handoff associations.

The resulting transition is only to existing independent verification. Wrong
code fails checks, out-of-scope edits cannot issue a handoff, and missing required
review prevents acceptance. Worker stdout claiming success, model, session or
usage remains untrusted capture text. Model/session/token/cost observations stay
unknown. Existing cancellation, effects, budgets, candidate freezing, protected
paths and required ReviewSensei evidence continue to apply. Local cancellation
is not remote cancellation or proof that billing stopped.

Synthetic tests exercise the public detached RunService path exactly once,
repeated start after reopening, independent command verification and negative
cases for wrong code, scope, cancellation, stale authority/leases, tampering,
workspace drift, uncertain cessation and incomplete durable retention. They
qualify this original fixture contract only. Actual Muse executable closure,
account/model/allowance, tool/filesystem/network isolation, descendant tracking,
effective finite usage bounds and installed independent reviewer remain separate
live-route prerequisites. The [protocol preparation](0011-muse-offline-protocol.md)
records the official evidence and unresolved semantic protocol dependency.
