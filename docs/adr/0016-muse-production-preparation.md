# Durable production Muse preparation

Status: proposed. Production dispatch remains disabled.

The existing v2.11 intent registers requested executable/policy/model identities
and always refuses submission before lifecycle allocation. Local preparation can
add useful measurements without pretending to supply the missing production
packet, admission, containment or recovery contracts.

Choose a separate `muse_preparation` module behind thin RunService/CLI methods.
An alternative is to extend the synthetic v2.9 driver and handoff; that would
reinterpret fixture contracts as production and is rejected. Another is to accept
an imported receipt with caller-set qualification flags; hashes and asserted
producer names do not authenticate runtime facts, so that is also rejected.

Preparation measures direct bounded files, checks registered instruction/tool
hashes, binds the full immutable Git base manifest and records a symbolic closed
argv plan with requested budgets. An immutable content-addressed private settings
record separates measured identities from explicit unqualified runtime facts.
It retains no original input bytes or prepared prompt. A later qualified owner
must create and bind the actual prompt/workspace/packet after durable admission.

Reopen validates the record and reobserves the exact subject; drift refuses
without rewriting history. Same inputs return the same identity. The source base
stays pinned when a clean HEAD moves. No run, attempt, effect, authority, lease,
workspace or acceptance exists, so additive settings need no Store migration.
Older readers ignore these settings and continue to reject v2.11 execution.
Rollback removes code support while preserving settings; no version lowering or
history deletion is necessary.

Tests use public API/CLI, original disposable files and a sentinel executable.
They cover idempotency, reopen, mutable inputs, malformed/unsafe/oversized inputs,
forged records, pinned source identity, existing-run preservation and actual kill
before transaction commit. Packaging audits include module/test/docs and generated
guides. This evidence cannot enable a real runtime.

Full production integration remains a separate gated extension through the one
Workflow/Store/process owner: actual executable/instruction/tool closure,
filesystem/network containment, authenticated account/endpoint/model/allowance,
enforceable aggregate inference bounds, complete child lifetime, original output
captures, durable completion/no-replay recovery and independent real review must
be established. Unknown effects and historical holds retain their meaning.
