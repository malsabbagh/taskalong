# E1 offline single-provider trial preparation

Status: proposed for review with this change.

The earliest real developer trial needs exact task, worker, independent reviewer
and draft-target identities before any provider is enabled. Existing synthetic
families cannot be relabeled as production, and a complete review JSON result
cannot authenticate its producer or express a native App approval.

Add ten closed family 2.8 resources and pure readers in `trial.py`. The new
worker-result copies the neutral 2.5 shape with an explicit production contract;
2.5's synthetic meaning and all earlier resource bytes remain unchanged. An
acyclic packet/projection mapping binds canonical bytes, exact run, attempt,
lease, config, provider, admission and activation identities. Reading or storing
these documents performs no execution and grants no authority.

Use the existing backed-up, exclusive maintenance path for format 8 / SQL008.
It is a compatibility fence using existing tables. Never auto-upgrade, lower a
version integer to roll back, or introduce a second lifecycle database. The
retained format 7 reader must refuse format 8 before journal changes. Existing
families remain readable on the new format. Registration is immutable history;
the closed executor registry contains no E1 factory. Operational 2.8 submissions
and stored runs refuse with `trial_runtime_unqualified` before replay, guards,
repository inspection, reservations, credentials, processes or effects.

`trial_review.py` validates supplied original captures against the four pinned
raw ReviewSensei 0.8.12 schemas without importing its engine or discovering a
schema. It preserves raw exit/status, complete coverage and distinct finding
instances. Observation completeness means consistent supplied text and process
evidence; it does not authenticate an installation. Runtime-only upstream
classifications absent from the serialized schema are not invented. Unknown
tokens, cost and remote effects do not become zero or stopped claims.

`trial_control.py` separately records history, reports structural gaps and checks
assessment consistency against original captures and current stored OS authority
and policy. A separately attributed assessment cannot change the CLI receipt.
An assessed false allegation remains a no-change engineering judgment, not a
verified fix. Genuine unfixed defects, optional or required, block consistency.
Missing decisions remain awaiting assessment. Even consistent decisions retain
an unknown installation qualification and blocked aggregate local-review gate.
No new authorizer, signer, model fallback or credential mechanism is introduced.
Existing verification authority must bind the exact assessment intent, including
the preselected authority ID and every judgment; a generic task grant does not
authorize it. The authority hash is attached afterward to avoid a digest cycle.
Each raw stream must also agree with the fixed standard redacted ProcessResult
representation; total output length alone cannot establish capture consistency.

The existing public service can already recover the completed worker handoff
before first verification. A synthetic regression observes the real controller
at that boundary, kills the owned controller, reopens the same store and verifies
once. It checks retained edits, attempt/effect identities and monotonically
consumed budgets. Unknown cessation or pending effects still refuse. This is
workflow recovery, not native session continuation or real trial completion.

The next enablement change must name a concrete authorized host, installed
worker/reviewer closures, provider/model/account, bounded permitted data and
repository target. It must independently prove instruction/tool/check isolation,
cancellation and owned descendant cessation, accounting and results for that
exact route. No further dormant adapter layer substitutes for those facts.
M2 production admission remains false. Planned sequential-step work keeps its
2.7 namespace; if format 8 lands here first, its later migration must use the
next actual available number and pin the resulting predecessor.

The real trial must reproduce an agreed bug RED, fix it GREEN, survive the
completed-worker interruption, invoke the actual installed local reviewer before
the draft PR, reach actual complete exact-head native App APPROVED, and retain
elapsed time, interventions, rework and unsupported steps. The user is the final
merge gate for that trial PR. This preparatory change proves none of those real
provider outcomes and includes no registry publication.
